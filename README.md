# AveTrack

Личный таск-менеджер в духе Apple Reminders с трекером заработка и Telegram-ботом.
Один пользователь, mobile-first, устанавливается на главный экран телефона как приложение (PWA).

- **Задачи**: списки, умные списки (Сегодня, Запланированные, Все, С флажком, Выполненные), подзадачи, приоритеты, флажки, повторы как в Reminders, свайпы, перетаскивание, быстрое добавление.
- **Деньги**: заработок за неделю, месяц, год или всё время, цели с прогрессом, график по месяцам.
- **Telegram**: утренняя и вечерняя сводки с кнопками «✓», отчёт по доходам, напоминания о задачах со временем, команды `/today`, `/tomorrow`, `/money`, `/add`.

## Стек

Next.js 15 (App Router) · TypeScript · Tailwind CSS 4 · Framer Motion · SQLite (better-sqlite3 + Drizzle ORM, WAL) · grammY · node-cron · date-fns / date-fns-tz · zod · Vitest.

Два процесса работают с одним файлом SQLite:

| Процесс | Что делает | Запуск |
|---|---|---|
| `web` | интерфейс и server actions | `npm run dev` / `npm start` |
| `worker` | Telegram-бот (long polling) и планировщик раз в минуту | `npm run worker` |

## Быстрый старт (локально)

Нужен Node.js 22.9+.

```bash
npm ci
cp .env.example .env
```

В `.env` задайте как минимум `APP_PASSWORD` и `SESSION_SECRET` (`openssl rand -hex 32`), а для работы по http — `COOKIE_SECURE=false`.

```bash
npm run dev
```

Откройте http://localhost:3000 и войдите с паролем. База `./data/avetrack.db` и миграции создаются автоматически при первом запуске.

Бот запускается во втором терминале (после настройки Telegram, см. ниже):

```bash
npm run worker
```

### Полезные команды

| Команда | Что делает |
|---|---|
| `npm test` | unit- и интеграционные тесты (Vitest) |
| `npm run typecheck` | проверка типов |
| `npm run build` | production-сборка (standalone) |
| `npm start` | запуск production-сборки |
| `npm run db:generate` | новая миграция после изменения `src/shared/db/schema.ts` |
| `npm run db:migrate` | применить миграции вручную (обычно не нужно — они применяются при старте) |
| `npm run backup` | бэкап базы |
| `npm run icons` | пересоздать PNG-иконки PWA |

> Не запускайте `npm run build`, пока работает `npm run dev`: у них общая папка `.next`, и dev-сервер начнёт отвечать ошибкой 500. Если это случилось, удалите `.next` и перезапустите dev.

## Telegram-бот

### 1. Создать бота через @BotFather

1. В Telegram откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Введите имя (например, `AveTrack`) и username, который заканчивается на `bot` (например, `my_avetrack_bot`).
3. BotFather пришлёт токен вида `1234567890:AA...`. Это `TELEGRAM_BOT_TOKEN`. Никому его не показывайте: при утечке выпустите новый командой `/revoke`.
4. Необязательно: `/setuserpic` (аватар бота) и `/setdescription`.

Список команд (`/today`, `/add`, `/help`) worker регистрирует сам при запуске.

### 2. Узнать свой chat_id

1. Найдите своего бота в Telegram и отправьте ему любое сообщение, например `/start`.
2. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, подставив токен.
3. В ответе найдите `"chat":{"id":123456789,...}`. Это число и есть `TELEGRAM_CHAT_ID`.

Если ответ пустой, напишите боту ещё раз и обновите страницу. Пока worker запущен, он сам забирает апдейты, поэтому на время этого шага его нужно остановить. Можно и проще: [@userinfobot](https://t.me/userinfobot) присылает ваш id.

### 3. Подключить

Пропишите обе переменные в `.env`, перезапустите web и worker. В приложении откройте **Настройки → Уведомления → «Отправить тестовое сообщение»**.

### Как работает

- **Утренняя сводка** приходит в заданное время (по умолчанию 08:00, часовой пояс из настроек, по умолчанию Europe/Amsterdam). В ней задачи на сегодня и просроченные, сгруппированные по спискам, с отметками приоритета. Под сообщением — кнопка «✓» для каждой задачи: после нажатия задача выполняется, а сводка перерисовывается с зачёркиванием. Повторяющаяся задача переносится на следующую дату. Если задач нет, приходит короткое сообщение.
- **Вечерняя сводка** (по умолчанию 18:00) — три сообщения подряд:
  1. 🌙 что не выполнено сегодня, включая просроченное, с кнопками «✓»;
  2. 📅 задачи на завтра, тоже с кнопками;
  3. 💰 доходы за текущий месяц: итог, среднее в день, сравнение с прошлым месяцем на ту же дату, источники и прогресс целей.

  Если одно из сообщений не ушло (например, пропала сеть), следующие не отправляются вне очереди: через минуту цепочка продолжится с того же места.
- **Напоминания**: о задаче со временем бот пишет отдельно в это время, с кнопкой «✓ Выполнено».
- **Команды**: `/today` — задачи на сегодня, `/tomorrow` — на завтра, `/money` — доходы за месяц, `/add Купить хлеб` — задача во «Входящие» на сегодня, `/emoji` — свои премиум-эмодзи.
- **Премиум-эмодзи**: если у владельца бота (аккаунта, который создал его в @BotFather) есть Telegram Premium, вместо обычных эмодзи можно использовать свои. Отправьте боту `/emoji`, чтобы увидеть места (утро, вечер, деньги, готово…), затем, например, `/emoji вечер` и премиум-эмодзи из своих наборов. `/emoji вечер сброс` возвращает обычный эмодзи для одного места, `/emoji сброс` — для всех. Если Telegram перестанет принимать премиум-эмодзи, бот отправит те же сообщения с обычными.
- **Защита от дублей**: перед отправкой worker делает запись в `sent_notifications` с уникальным ключом и только потом отправляет. Поэтому перезапуск worker'а или второй экземпляр не пришлют уведомление повторно. Если отправка не удалась (нет сети), запись снимается и попытка повторяется через минуту. После простоя worker догоняет сводку в течение 4 часов, а напоминание — в течение часа.
- Бот отвечает только чату `TELEGRAM_CHAT_ID`, остальные сообщения игнорирует.
- Время утренней и вечерней сводок, часовой пояс и их включение меняются в **Настройках**. Worker читает их каждую минуту, перезапуск не нужен.

## Деплой на VPS

Для PWA (установка на главный экран, service worker) и безопасной cookie нужен **HTTPS**. Проще всего поставить перед приложением [Caddy](https://caddyserver.com): он сам получает сертификат Let's Encrypt. Пример `/etc/caddy/Caddyfile`:

```
track.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

DNS-запись домена должна указывать на сервер. В `.env` пропишите `APP_URL=https://track.example.com`.

**Без своего домена** подойдёт бесплатный адрес [sslip.io](https://sslip.io): имя вида `31-76-11-103.sslip.io` (IP сервера через дефисы) само указывает на этот IP, регистрироваться нигде не нужно. Подставьте его в Caddyfile вместо домена — Caddy получит на него обычный сертификат.

Caddy удобно запустить контейнером рядом с приложением:

```bash
mkdir -p /opt/caddy && printf '31-76-11-103.sslip.io {\n  reverse_proxy 127.0.0.1:3000\n}\n' > /opt/caddy/Caddyfile
docker run -d --name caddy --restart unless-stopped --network host \
  -v /opt/caddy/Caddyfile:/etc/caddy/Caddyfile -v caddy_data:/data caddy:2
```

### Вариант 1. Docker Compose

```bash
git clone <репозиторий> avetrack && cd avetrack
cp .env.example .env   # заполнить APP_PASSWORD, SESSION_SECRET, TELEGRAM_*, APP_URL
mkdir -p backups && sudo chown 1000:1000 backups   # контейнеры работают от пользователя node (uid 1000)
docker compose up -d --build
docker compose logs -f worker   # убедиться, что бот запустился
```

- Два сервиса `web` и `worker` и общий том `avetrack-data` с базой в `/data/avetrack.db`.
- Web слушает `127.0.0.1:3000`, наружу его выпускает reverse proxy. Без прокси замените в `docker-compose.yml` на `"3000:3000"`.
- Обновление: `git pull && docker compose up -d --build`. Миграции применяются автоматически.

### Вариант 2. Без Docker, через PM2

```bash
# Node.js 22.9+ и инструменты сборки (на случай, если для платформы нет готового better-sqlite3)
sudo apt install -y build-essential python3
sudo npm install -g pm2

git clone <репозиторий> avetrack && cd avetrack
cp .env.example .env   # заполнить
npm ci
npm run build

pm2 start ecosystem.config.cjs
pm2 save
pm2 startup   # выполнить команду, которую он выведет, — автозапуск после перезагрузки
```

`ecosystem.config.cjs` поднимает три процесса:

| Процесс | Назначение |
|---|---|
| `avetrack-web` | приложение на `127.0.0.1:3000` (`scripts/start.mjs`) |
| `avetrack-worker` | бот и планировщик |
| `avetrack-backup` | бэкап базы каждый день в 03:30 по времени сервера (запускается по cron и завершается) |

Логи — `pm2 logs`, статус — `pm2 ls`. Обновление:

```bash
git pull && npm ci && npm run build && pm2 reload ecosystem.config.cjs
```

## Бэкапы

`scripts/backup.mjs` делает согласованную копию через SQLite online backup API. Это безопасно при работающих web и worker; простой `cp` в WAL-режиме мог бы скопировать базу без последних изменений. Каждая копия проверяется (`quick_check`) и сохраняется одним файлом `avetrack-<дата-время>.db`. Хранятся последние `BACKUP_KEEP` копий (по умолчанию 14).

| Где | Как запускать |
|---|---|
| вручную | `npm run backup` |
| PM2 | процесс `avetrack-backup`, каждый день автоматически |
| системный cron без Docker | `30 3 * * * /path/to/avetrack/scripts/backup.sh >> /path/to/avetrack/backups/backup.log 2>&1` |
| Docker (cron на хосте) | `30 3 * * * cd /path/to/avetrack && docker compose exec -T worker npm run backup >> backups/backup.log 2>&1` — файлы появятся в `./backups` на хосте |

Копии стоит иногда уносить с сервера (rsync, облако): бэкап на том же диске не спасёт от его отказа.

**Восстановление:**

1. Остановите web и worker (`docker compose stop` или `pm2 stop all`).
2. Скопируйте нужный файл на место базы. В Docker: `docker compose cp backups/avetrack-….db web:/data/avetrack.db`.
3. Удалите рядом лежащие `avetrack.db-wal` и `avetrack.db-shm`, если они есть.
4. Запустите сервисы снова.

## Установка на телефон (PWA)

- **iPhone**: откройте адрес в Safari → «Поделиться» → «На экран „Домой“».
- **Android**: Chrome → меню → «Установить приложение».

Приложение открывается без интерфейса браузера и учитывает вырез экрана и home indicator. Без сети вместо ошибки показывается офлайн-страница.

## Устройство проекта

```
src/
  app/                    роутинг Next.js: тонкие страницы, логика — в features
  features/
    auth/                 вход по паролю, HMAC-подписанная cookie на 90 дней
    tasks/                задачи: чистая модель (model.ts), запросы к БД, server actions, UI
    recurrence/           правила повтора: схема, вычисление дат, описание
    lists/                списки и умные списки
    money/                записи, цели, графики
    settings/             настройки (ключ–значение в БД)
    telegram/             форматирование сообщений, бот, планировщик
  shared/                 БД, UI-компоненты, утилиты дат и денег, реестр навигации
  worker/                 точка входа worker'а
drizzle/                  SQL-миграции
scripts/                  запуск, миграции, бэкап, иконки
```

Принципы:

- **Бизнес-логика — в чистых функциях** без БД и UI (`model.ts`, `recurrence/next.ts`, `telegram/format.ts`, `telegram/schedule.ts`), они покрыты тестами. Клиент и сервер считают одно и то же одними функциями, поэтому оптимистичный UI совпадает с тем, что сохранит сервер.
- **Оптимистичные обновления**: действие сразу видно в интерфейсе, server action подтверждает его в фоне, при ошибке состояние откатывается и показывается тост.
- **Даты задач** хранятся как локальные `YYYY-MM-DD` и `HH:mm` в часовом поясе из настроек, поэтому переходы на летнее и зимнее время ничего не сдвигают. Суммы денег хранятся в центах.

### Повторы

Правило хранится в `tasks.recurrence` как JSON, а не RRULE. Его валидирует zod, а нужное подмножество RFC 5545 считает маленькая проверяемая функция (`src/features/recurrence/next.ts`) без проблем rrule.js с часовыми поясами.

```json
{ "freq": "week", "interval": 2, "weekdays": [1, 3], "end": { "type": "count", "count": 10 } }
{ "freq": "month", "interval": 1, "monthly": { "type": "nth", "nth": 2, "weekday": 2 }, "end": { "type": "never" } }
```

Когда повторяющаяся задача отмечена выполненной, факт записывается в `task_completions`, а задача переезжает на первое вхождение после большей из двух дат: срока задачи и сегодняшнего дня. Пропущенные вхождения не копятся. 31-е число в коротких месяцах прижимается к последнему дню месяца.

### Новый модуль

1. Создайте `src/features/<модуль>/` по образцу `money`: `model.ts` (чистая логика и тесты), `server.ts`, `actions.ts`, `components/`.
2. Если нужна таблица — добавьте её в `src/shared/db/schema.ts` и выполните `npm run db:generate`.
3. Добавьте страницу `src/app/(app)/<модуль>/page.tsx` и запись в `src/shared/navigation/nav.ts`: пункт появится в таб-баре.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Не получается войти, страница входа снова открывается | Приложение открыто по http, а `COOKIE_SECURE=true`. Настройте HTTPS или временно поставьте `COOKIE_SECURE=false`. |
| Бот молчит | Посмотрите логи worker'а (`pm2 logs avetrack-worker` / `docker compose logs worker`), проверьте `TELEGRAM_*` и отправьте тест из настроек. Бот отвечает только своему `TELEGRAM_CHAT_ID`. |
| Сводка пришла не в то время | Проверьте часовой пояс в **Настройках** — он задаётся там, а не на сервере. |
| `npm ci` падает с `EPERM ... unlink ... .node` (Windows) | Файлы `node_modules` заняты запущенным процессом. Остановите `npm run dev` / `npm run worker` (Ctrl+C) и повторите. Пока сервер работает, `npm ci` не нужен. |
| `npm ci` падает на better-sqlite3 | Нет готового бинарника для платформы: установите `build-essential python3` (Linux) или Visual Studio Build Tools (Windows) и повторите. |
| Dev-сервер отвечает 500 после `npm run build` | Удалите `.next` и перезапустите `npm run dev`. |
